## 1. Purpose

NC-028 is the hospital's **IT service desk**: a single place for staff to raise IT/HMS issues and requests (login, access rights, hardware, printer, network, HMS bug/how-to, report needs, integration failures, device replacement) via web/mobile/QR/chatbot/email/phone, with **categorised routing, priority & SLA (P1–P4)**, escalation, assignment to L1/L2/vendors, resolution notes and closure with requester confirmation; an **IT asset issue log** (asset ↔ tickets, allocation/replacement, spares), **problem & change management** (RCA for recurring incidents; controlled changes to HMS config/integrations/servers with CAB approvals & rollback plans), **knowledge base** & self-service (password reset, printer setup guides), **major incident/downtime procedures** (HMS downtime declaration → EN-018 banners, downtime forms, recovery), auto-tickets from monitoring (integration hub, printers, backups, kiosks), vendor/SaaS L3 bridge, and NABH IMS evidence & IT KPIs.

## 2. Users & Jobs-to-be-done

- **Staff requester** (web/NC-014/QR on device/WhatsApp/phone): raise ticket in < 30 s (category chips, asset from QR, screenshot), track status, chat with agent, confirm resolution, rate.
- **L1 agent** (desktop): triage queue, classify/prioritise, resolve from KB (password unlock via EN-007, printer restart), remote support, escalate to L2/vendor, log time; walk-up desk & phone.
- **L2/System admins**: technical resolution, integration errors (EN-017 DLQ replay), server/network changes (change requests), asset swap; problem RCA.
- **IT manager**: SLA dashboards, staffing, vendor escalations, change advisory board, major incident commander, licence & asset planning, NABH IMS reports.
- **HOD**: approve access/hardware requests for their staff.
- **BME/Facility**: cross-routed tickets (device interfaces, cabling/power).
- **Vendor/SaaS support**: tickets forwarded via portal/API; updates sync back.

## 3. Core Workflows

### 3.1 Ticket intake & classification

1. **Requester** creates ticket: channel enum(web/mobile/qr_asset/email/phone/walkup/chatbot/whatsapp/monitoring), type enum(incident/service_request/access_request/hardware_request/how_to/report_request/enhancement/data_correction), category tree (HMS module (OPD/Billing/Lab/…)/login & access/hardware (PC/printer/scanner/tablet/kiosk/TV)/network & Wi-Fi/email/telephony/integration (LIS/PACS/ABDM/SMS/payment)/server & backup/security/other), location/asset (QR → NC-002 asset id), description, screenshot/video, impact enum(single_user/department/critical_service/hospital_wide) & urgency → **priority matrix** P1 (critical service down: billing/registration/ER/lab/PACS hospital-wide), P2 (department down/patient-facing degraded), P3 (single user impaired), P4 (request/how-to) → SLA (response/resolution: P1 15 min/2 h; P2 30 min/8 h; P3 4 h/2 d; P4 1 d/5 d — config; 24×7 for P1/P2, business hours others) → auto-assign to group (routing rules by category/location; on-call for P1) → acknowledgement to requester → Event `helpdesk.ticket.created`.
2. **Auto-tickets** from monitoring: EN-017 connector failures/DLQ growth, EN-005 printer offline/queue stuck, EN-018/EN-034 device offline, EN-022 backup failed, EN-023 SIEM alerts (security category → restricted), Sentry error spikes for a module, EN-042 device gateway; dedupe by fingerprint; auto-close on recovery with note.
3. **Access requests**: role/permission/branch/department scope changes → HOD approval (EN-038) → IT executes in EN-007 (or auto-provision templates) → SoD checks (EN-007 policy) → evidence attached; joiner/mover/leaver tickets from NC-010 events with checklists (accounts, devices, licences, revocations within SLA).

### 3.2 Triage, work & resolution

1. **Agent** picks ticket (or auto-assigned) → validates priority (adjust with reason) → KB suggestions → actions (remote session `helpdesk.remote_support` link, password reset via EN-007 API with identity verification per policy, printer re-map, asset swap from spare pool (NC-002 allocation), integration replay (EN-017), config change → change request if beyond standard change) → status enum(new/assigned/in_progress/waiting_requester/waiting_vendor/waiting_change/resolved/closed/reopened/cancelled) with SLA clock pausing only in `waiting_requester` (and vendor if contract says so) → resolution code & notes, time spent, parts used → **resolved** → requester confirmation (auto-close after 3 days) → CSAT rating → Event `helpdesk.ticket.resolved|closed`.
2. Escalations: SLA breach warnings (80 %) & breaches → team lead → IT manager → CIO (EN-038 ladder); P1 → major-incident bridge (3.4); vendor tickets → NC-021 vendor SLA tracking; SaaS L3 (`helpdesk.saas_vendor_bridge`): forward to Vim's HMS support (EN-040 tier) with diagnostics bundle (no PHI: request ids, timestamps, logs scrubbed) → status sync.
3. Reopen within 7 days links to same ticket; recurring (≥ 3 similar in 30 days) → **problem** record.

### 3.3 Problem & change management (`helpdesk.itil_change`)

- **Problem**: linked incidents, RCA (5-why/fishbone template), known-error & workaround (KB), permanent fix via change; closure.
- **Change request**: type enum(standard/normal/emergency), description, risk/impact (services affected, downtime window), rollback plan, test evidence, CAB approvals (EN-038: IT manager + affected HODs + security for risky), schedule (maintenance window, EN-018 downtime notice), implementation log, post-implementation review; changes to HMS masters/config with clinical impact require MS/Quality sign-off; emergency changes documented within 24 h → Event `helpdesk.change.approved|implemented`.

### 3.4 Major incident & HMS downtime procedure (NABH IMS)

- Declare major incident (P1 hospital-wide) → incident commander, bridge chat/room, status page & EN-018 TV banner ("HMS downtime — use downtime forms"), SMS to HODs (EN-009), **downtime kit**: printable downtime registration/billing/lab forms (EN-039), read-only cached views (PWA offline: patient banner/last results per module rules), numbering reservation ranges; recovery: back-entry tasks per department with reconciliation checklist; RCA within 72 h; NABH IMS record; DPDP/CERT-In notifications if data incident (with EN-023/NC-023).

### 3.5 IT asset issue log & lifecycle (with NC-002)

- Ticket ↔ asset link; asset issue history & MTBF; replacement/repair via NC-002 service call; spare pool (laptops/PCs/scanners/printers) issue-return; consumables (toner) requests → NC-006 issue; software licence register (product, seats, expiry, assigned users) with compliance alerts; end-user device standards & imaging checklists; onboarding kits.

### 3.6 Knowledge base & self-service (`helpdesk.kb`, `helpdesk.chatbot_l0`)

- Articles (how-to per HMS module with screenshots/videos, printer setup, VPN, common errors), versioned (NC-004), role-visible; search from ticket form (deflection); AI-001 chatbot L0 (password reset flow with OTP, printer troubleshooting, ticket status) with hand-off; announcements (planned downtime, new features) via NC-014/EN-018.

### 3.7 Device & integration health board

- Live board: printers online (EN-005), kiosks/TVs (EN-018/EN-034), integration connectors & queues (EN-017), analyzers/PACS links (EN-004/EN-008), Wi-Fi APs (SNMP via EN-042 optional), servers/backups (EN-022) → click → ticket; uptime KPIs for NABH IMS.

## 5. Business Rules & Validations

- Priority = f(impact, urgency) matrix; P1 requires phone/on-call paging (EN-037 escalation) and major-incident evaluation within 15 min; requester cannot set P1 directly (agent confirms) except pre-authorised roles (ER/billing in-charge).
- SLA clock: business-hours calendar for P3/P4, 24×7 for P1/P2; pauses only in defined states; breach → escalation ladder; SLA profile per category can override.
- Password reset/unlock: identity verification (employee ID + registered mobile OTP or manager confirmation) logged; never share passwords in tickets; access requests need HOD approval and SoD check; execution evidence mandatory; leaver revocation ticket SLA ≤ 1 h from `hr.employee.exited`.
- Changes: normal changes need CAB approval & maintenance window; emergency changes need IT manager verbal + documented within 24 h; changes touching clinical masters (drug master, tariffs, order sets) require domain owner sign-off; every change links to affected services and a rollback plan; freeze windows (month-end billing, NABH audit days) block normal changes.
- Auto-tickets deduped by fingerprint (open ticket exists → append event, bump count); auto-resolve on recovery signal with note; flapping suppression (≥ 3 in 1 h → single ticket).
- Ticket close only by requester confirmation or auto after 3 days; reopen within 7 days; CSAT optional; PHI guard on free text (UHID/phone patterns → warning; blocked in public KB).
- Vendor tickets: SLA per NC-021 contract; vendor updates via portal/API; SaaS bridge scrubs PHI.
- Numbering `TKT`, `PRB`, `CHG`, `MI` per hospital/FY.

## 13. Non-functional

- Volumes: 5k staff → 150–300 tickets/day (go-live peaks 1,000/day), 200 auto-tickets/day, 500 KB articles; ticket create p95 < 200 ms; queue realtime; email/WhatsApp intake < 1 min.
- Availability: helpdesk must work in HMS degraded mode — separate lightweight status page & ticket intake (static PWA + queue) hosted independently; phone/WhatsApp fallback documented.
- Security: RLS; restricted security tickets; PHI guard; attachments AV-scanned; audit; CERT-In log retention (EN-024).
- Offline: mobile ticket creation queues; agent console online.
- i18n; WCAG 2.2 AA; TV mode for health board & MI status; printing of downtime forms (EN-039).

## 14. Acceptance Criteria

1. Given a receptionist scans a printer QR and reports "not printing" with a photo, then a ticket is created with asset linked, category printer, P3, routed to the L1 desk group, and she receives ticket no. & ETA within 5 s.
2. Given billing goes down hospital-wide and an in-charge raises P1, then on-call IT is paged within 1 min, a major-incident record is prompted, and if downtime is declared, EN-018 shows the banner and HODs get SMS.
3. Given a P2 ticket with 8 h resolution SLA in `waiting_requester` for 3 h, then the SLA clock pauses those 3 h and resumes on requester reply.
4. Given an access request for `billing.bill.discount.approve`, then HOD approval is required; on approval IT executes via EN-007 and the SoD check flags if the user already has `billing.bill.create` per policy.
5. Given `hr.employee.exited` at 10:00, then a leaver ticket with 1 h SLA is created; if accounts are not disabled by 11:00, escalation to IT manager occurs.
6. Given EN-017 reports LIS connector down 3 times within 1 hour, then one ticket exists with count 3 (flapping suppression); on recovery, the ticket auto-resolves with a note.
7. Given a normal change to modify the drug master import job scheduled in the month-end freeze window, then scheduling is blocked; emergency type requires IT manager approval and documentation within 24 h.
8. Given a ticket resolved on Monday with no requester confirmation, then it auto-closes Thursday; requester can reopen within 7 days and the same ticket reopens.
9. Given a KB article suggested during ticket creation is marked "solved my issue", then no ticket is created and a deflection event is recorded.
10. Given a ticket description containing a UHID and phone number, then the requester sees a PHI warning and the SaaS forward scrubs those patterns.
11. Given a user without agent permissions opens another user's ticket URL, then 403/404 and audit entry.
12. Given the month's data, then NABH IMS report shows HMS availability %, downtime episodes with durations, and change success rate.
