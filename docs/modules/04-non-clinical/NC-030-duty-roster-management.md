## 1. Purpose

NC-030 plans **who works when and where** across a 24×7 hospital: shift definitions & patterns, monthly/weekly rosters per department/ward/unit with **required coverage** derived from beds/census/acuity (nurse–patient ratios, skill mix e.g. ≥ 1 ICU-competent nurse per shift), auto-assignment honouring rules (fatigue: max consecutive nights, min rest 11–12 h, weekly hours cap, no back-to-back double shifts without approval; leave/holidays; competencies/certifications; preferences & fairness), **swap/shift-change marketplace** with approvals, on-call/standby rosters with escalation directory (feeds EN-037 routing), locum/visiting/pool staff, floating pool & redeployment during surges (IP-025), publishing to staff (NC-014), variance tracking vs attendance (NC-029), and staffing analytics for NABH & cost. It supports nurses first (Phase 7) and all departments (Phase 9).

## 2. Users & Jobs-to-be-done

- **Nurse supervisor/Matron** (desktop; tablet on rounds): build ward rosters for next month in < 30 min per unit using templates & auto-assign; ensure ratios & skill mix per shift; handle leave, swaps, sick calls (find replacement from float pool/off-duty willing list); real-time "who is on duty" per ward; redeploy staff on surge; publish.
- **HOD/in-charge** (desktop/mobile): department rosters (residents' rotations, on-call, technicians), approve swaps, view coverage gaps.
- **Employee** (NC-014): my roster (calendar), shift reminders, request swap/shift change/leave (NC-010), set preferences/availability (`roster.self_scheduling`), accept open-shift offers, on-call acknowledgements.
- **HR**: shift catalogue & rules (statutory), roster locking for payroll (NC-029/NC-010), night-shift compliance for women, contractor plans.
- **ER/OT/ICU in-charges**: code team & on-call lists per shift; ensure OT list staffing.
- **MS/Quality**: ratio compliance dashboards, on-call adherence, fatigue exceptions.

## 3. Core Workflows

### 3.1 Shift catalogue, patterns & coverage requirements

1. **HR/Supervisor** defines **shifts** (code, name, start/end, break, is_night, colour; e.g. M 07–14, E 14–21, N 21–07 or 12-h D/N; split; general 09–17; on-call/standby), **patterns/rotations** (e.g. M-M-E-E-N-N-Off-Off; resident rotations), **units** (ward/ICU/OT/ER/lab/pharmacy/housekeeping zone/security post) with **coverage rules** per shift: min headcount by role/grade (staff nurse, senior, in-charge, GDA), **ratio rule** (`roster.acuity_staffing`: required nurses = ceil(occupied_beds ÷ ratio) with acuity uplift from IP-003/IP-009 scores; ICU 1:1 ventilated), **skill requirements** (≥ N with competency X from NC-027; ≥ 1 BLS/ACLS; language), constraints (max nights per month, min rest, weekly hours), fairness (rotation of nights/weekends), preferences allowed → Event `roster.config.updated`.

### 3.2 Roster building & auto-assign (`roster.auto_assign`)

1. **Supervisor** creates roster period (month/fortnight/week) for unit(s) → **System** pre-fills: leave (NC-010 approved), holidays/weekly-offs, training sessions (NC-027), pattern rotation continuation, fixed assignments (in-charges), on-call rotations → computes **coverage demand** per shift (from rules + IP-025 occupancy forecast/planned OT lists IP-006/ER seasonality) → **auto-assign** engine (constraint solver: satisfy coverage & skill mix, respect fatigue/legal rules & availability/preferences, balance nights/weekends/hours across staff, minimise OT/agency) → gaps & rule violations highlighted → supervisor edits (drag/drop, bulk) with live validation (hard rules block; soft rules warn with reason) → **publish** (versioned; changes after publish tracked & notified) → Event `roster.published`.
2. Multi-unit/float pool: pool staff assigned to units per shift; cross-unit borrowing with competency check; contractor rosters (housekeeping/security via NC-021 plans) in same engine (`contractor` flag).
3. Doctors: consultants' OPD timings from OP-001 shown read-only; residents'/junior doctors' duty rota, ward coverage, on-call built here; OP-001 consumes availability for slot blocking (leave/on-call/off).

### 3.3 Daily operations: no-shows, sick calls, surges

1. NC-029 punches vs roster → **no-show** at shift start + grace (e.g. 15 min) → supervisor alert → **replacement finder**: ranks candidates (float pool on duty, off-duty willing (opt-in list), staff finishing previous shift with rest rules OK for extension ≤ X h with OT approval, agency/locum `roster.locum`) → offer via push (first-accept wins) → assignment → OT/allowance flags to NC-029/NC-010 → Event `roster.shift.replaced`.
2. **Surge/redeployment**: IP-025 occupancy spike/mass casualty (OP-006 MCI) → recompute demand → suggest redeployment from lower-ratio units; supervisor confirms; staff notified.
3. Sick/emergency leave from employee (NC-010 quick leave) → auto-triggers replacement flow.

### 3.4 Swap & shift-change requests (`roster.swap_marketplace`)

1. **Employee** proposes swap (with a specific colleague or open to unit) or shift change/drop/pick-up (open shifts posted by supervisor) → **System** validates both parties' resulting schedules (rest, hours, nights cap, competency/ratio impact) → colleague accepts → in-charge/supervisor approval (auto-approve if all rules OK & policy allows) → roster updated, both notified, NC-029 mapping updated → Event `roster.swap.approved`.
2. Limits (max swaps/month), cut-off (e.g. ≥ 12 h before shift; emergencies via supervisor), audit.

### 3.5 On-call & escalation directory (`roster.oncall`)

- On-call rosters per specialty/service (surgery, ortho, anaesthesia, radiology, cardiology, paediatrics, blood bank, BME, IT, facility, security officer, administration) with primary/secondary/consultant tiers, phone numbers (from NC-010), acknowledgement requirement, handover time → **EN-037** uses "who is on-call now" API for routing critical alerts (OP-006 ER on-call alert, lab critical values, code teams IP-013), escalation after no-ack; on-call log (calls/attendance/response times) for NC-034 on-call payments & quality; post-call rest rules → Event `roster.oncall.changed`.

### 3.6 Preferences, self-scheduling & fairness (`roster.self_scheduling`)

- Employees submit availability/preferences (no nights on dates, preferred shifts, max shifts) within a window; supervisor sets weights; fairness metrics (nights/weekends/holidays distribution) shown; seniority rules; requests logged.

### 3.7 Locking, payroll & analytics

- Roster locked per day after attendance processing (NC-029) — actual worked shifts vs planned → variance (unplanned OT, absences, borrowed staff) → payroll inputs (night/shift allowances via NC-029), staffing cost vs budget (NC-022), NABH ratio compliance report per shift, fatigue-rule exceptions & approvals.

### 3.8 Auto-assign engine specification

- **Inputs**: period, units, employees (availability: leave/holiday/training/restrictions/credentials/competencies/contract hours), coverage demand per shift (headcount by role + skills), rules (hard/soft with weights), preferences (weighted), fairness state (carry-over nights/weekends from previous periods), fixed assignments, pattern continuation, contractor plans.
- **Method**: constraint solver in `services/worker` (CP-SAT via OR-tools or a greedy + local-search fallback if OR-tools unavailable on-prem) with time-box (default 30 s/unit-month; configurable), objective = minimise (uncovered demand × 1000 + hard-rule violations × ∞ + soft-rule violations × weights + fairness deviation × weights + preference violations × weights + projected OT cost); deterministic seed for reproducibility; partial results returned with unmet list.
- **Outputs**: assignments (source=auto), coverage report per shift, violations list, fairness stats delta, explanation per unmet slot ("no ICU-competent nurse available with rest ≥ 11 h").
- **Re-run modes**: full (draft only), incremental (fill gaps without changing published cells), what-if (compare scenarios e.g. 12-h vs 8-h shifts, hire 2 nurses).
- **Guardrails**: never overrides published cells unless supervisor selects "re-plan from date"; never violates hard rules; logs solver stats for tuning.

### 3.9 Roster edge cases

- Split units (ward with isolation bay), floating in-charge across two small units, trainee supervision ratio (≥ 1 senior per N trainees), maternity/pregnancy & medical restrictions (NC-010 flags: no nights/no heavy lifting), religious/holiday preferences (soft), notice period for roster changes (e.g. ≥ 48 h except emergencies), strike/absenteeism surge mode (temporary rule relaxations with MS approval & expiry), locum onboarding same-day (credential quick-check), students/interns rosters (education dept), night-shift transport list to NC-024, roster print for notice boards (legal display where required), audit for labour inspections (hours/rest evidence).

## 5. Business Rules & Validations

- Hard rules (block): overlapping assignments; min rest between shifts (default 11 h; 8 h with approval as exception); max consecutive nights (default 3–4), max consecutive working days (6), weekly-off required per 7 days, max hours/week (48; residents per policy), no assignment during approved leave/holiday off (unless holiday duty flagged), competency/certification required for unit (ICU/NICU/OT/dialysis) valid on date, women night-shift policy per state (consent + transport + safety flags), pregnancy/medical restrictions (NC-010 flag) → no nights/heavy duty, expired credentials (NC-010) block, contractor police verification (NC-019) block on sensitive posts.
- Soft rules (warn): coverage below ratio/skill mix, fairness deviation > threshold, preference violations, back-to-back E→M ("quick returns"), > 2 weekends in a row.
- Coverage: required nurses per shift = ceil(occupied ÷ ratio) with acuity uplift; published roster must meet coverage or carry supervisor acknowledgement of gap (with mitigation note); ratio compliance computed per shift from actual presence (NC-029) for NABH.
- Publish: versioned; post-publish changes notify affected staff; roster for date D locks after NC-029 day computation (edits only via variance records/approval).
- Swaps: both schedules re-validated; cut-off & limits; approvals per policy; audit; OT/allowance implications flagged.
- Replacement: candidates must satisfy hard rules; extension beyond shift needs OT approval (NC-029 policy) and max 4 h; locum shifts require credential check & NC-034 payout rate.
- On-call: at least primary per required service per day; ack SLA (e.g. 10 min) → escalate to secondary → consultant → HOD (EN-037); post-call rest applied next day (soft/hard per category).
- Preferences: honoured best-effort with weights; seniority tiebreak configurable; no PHI in preferences beyond flags.
- Auto-assign is advisory until supervisor publishes; solver time-boxed (≤ 30 s per unit-month) with best-found result.

## 13. Non-functional

- Volumes: 5k staff, 200 units, ~450k assignments/month; grid load for a 60-staff unit-month < 1 s; validation on edit < 100 ms; auto-assign per unit-month ≤ 30 s (worker, progress via WS); on-call "now" API p95 < 30 ms (Redis); publish fan-out notifications ≤ 1 min.
- Offline: mobile my-roster cached; supervisor grid online (draft autosave).
- Security: RLS; ABAC unit scope; phone numbers masked; audit on publish/changes/exceptions.

## 14. Acceptance Criteria

1. Given ICU-A with 20 occupied beds (8 ventilated) and ratio rule 1:1 ventilated/1:2 others, then required nurses for the shift = 8 + 6 = 14 and the coverage bar shows 14; publishing with 12 planned requires supervisor gap acknowledgement.
2. Given auto-assign for a 30-nurse ward month, then within 30 s a roster is produced with no hard-rule violations, coverage met where feasible, nights/weekends balanced within tolerance, and unmet slots listed.
3. Given a nurse assigned N on 5th and M on 6th (rest 0 h), then the edit is blocked (min rest 11 h); with supervisor exception approval (≥ 8 h rule) it is allowed and logged.
4. Given a nurse whose ACLS certificate expired, then assignment to ICU is blocked (or warned per config) and the reason cites NC-027.
5. Given a published roster where staff X calls in sick 30 min before shift, then supervisor's replacement finder ranks eligible candidates, pushes offers, first acceptance assigns, and OT flag is raised if extension.
6. Given a swap request between A (M on 10th) and B (E on 10th) that would give B two shifts in a day, then the request is rejected at validation with reason.
7. Given a valid swap approved, then both rosters update, both employees notified, and NC-029 maps punches to the new shifts.
8. Given on-call surgery primary does not ack a page within 10 min, then EN-037 escalates to secondary using NC-030 tiers and the no-ack is logged.
9. Given a woman employee assigned nights in a state requiring consent/transport, then the assignment requires the consent flag & transport arrangement noted, else blocked.
10. Given a roster published on 25th and changed on 28th, then version increments and only affected employees receive change notifications.
11. Given IP-025 forecasts occupancy surge in Ward 3 tomorrow, then demand recomputes and redeploy suggestions from Ward 5 (over-ratio) appear for supervisor confirmation.
12. Given a user with `roster.read` for Ward 2 only, then Ward 3 roster is not accessible (403).
13. Given an incremental auto-assign after two resignations mid-month, then published cells remain unchanged, gaps are filled from eligible staff, and the change summary lists only new assignments.
14. Given a nurse flagged pregnancy restriction (no nights) in NC-010, then any N assignment is blocked with the reason and existing future N shifts are highlighted for re-plan.
15. Given a "strike surge mode" approved by MS for 3 days relaxing max consecutive days from 6 to 8, then the relaxation applies only within the window, is logged, and expires automatically.
16. Given a same-day locum onboarded with valid registration but no BLS certificate on file, then assignment to ICU is blocked while general ward assignment proceeds with a warning; the locum shift emits `roster.shift.replaced` with `locum_ref` for NC-034.
17. Given a night shift roster published, then NC-024 receives the list of staff needing night transport (opted-in) for that date.
18. Given a labour inspection request, then the hours/rest evidence report for a chosen employee & month exports with shift times, rest gaps, weekly-offs and exceptions.
