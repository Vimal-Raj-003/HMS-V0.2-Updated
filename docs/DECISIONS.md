| D-27 | 2026-08-19 | **Login runs hospital-scoped with no acting user, and widens to every branch of that hospital inside the same transaction.** | `core.users` has RLS, so an unscoped session reads nothing — login could not find anybody. And the generated policy appends `(branch_id IS NULL OR branch_id = ANY(core.current_branch_ids()))` to any branch-scoped table, with `current_branch_ids()` empty when unset, so a session that has not yet chosen a branch reads none of its own `user_roles`. Since the branch scope is *derived from* the grants, that is a genuine chicken-and-egg; `docs/05`'s own flow resolves it by placing "choose branch (if >1)" after the password step. Codified in `currentTenantContext()` so no module repeats the mistake: omitting branch ids does not mean "all branches", it means none, and the symptom is an empty list or an INSERT rejected deep inside an audit call. | — |
| D-26 | 2026-08-19 | **`services/api` verifies the permission catalogue at boot rather than syncing it.** | `_grants` states `REVOKE INSERT, UPDATE, DELETE ON core.permissions FROM hms_app`.
